tyes.app · Image Revisions Flow · Spec v1.
Defines the client-facing revision request flow and the admin resolution flow for delivered images. Aligned with the v2 pricing model (revisions come from plan config, 1 per image on Campaign tiers). Complements Client Dashboard v2 and Admin Dashboard v2 specs.
Question first: does the client currently have a "Request revision" button on delivered images, or is the "Revision" status admin-only? (We saw "Revision: ORD-7BFD" in admin Recent Activity.) If the button exists, align it to the rules below. If it doesn't, build the flow below.
Core principle: the revision allowance is NOT hardcoded. It reads max_revisions_per_image from the plan config (already present in the admin Edit Plan modal): Free Image = 0 · Campaign 5 = 1 · Campaign 10 = 1 · Custom = per scope. This also fixes the current bugs: checkout summary showing "Revisions: 3 included" and My Orders showing "Rev 0/3".
Section 1 · Rules
  • Counter is per image (order item), not per order.
  • A revision can be requested only on a delivered item, within 7 days of its delivery.
  • No requests after the order is Approved or Cancelled.
  • Strategy-only orders (0 images): revisions UI hidden everywhere, including the "Rev X/Y" counter in My Orders.
  • Free Image (0 revisions): "Request revision" button never shown.
  • All revision displays read from plan config: checkout summary ("1 revision / image"), My Orders counter ("Rev 0/1"), item buttons.

Request modal
Title: "What should we change?" · Required textarea (min 20 characters) describing the change · Optional reference image upload · Submit button: "Send revision request". On submit: item status → "Revision requested", counter increments, button disabled at limit, order status → Revision, in-app + email notification to admin.
After the limit
Button is replaced by a subtle link: "Revision limit reached — contact us" (opens support chat/email). No hard dead-end.
Section 3 · Admin Flow (Orders → Order Detail → Order Items)
  • Item in "Revision requested" state shows the client's note + reference image inline.
  • Admin uploads the revised image to the same order item — stored as v2 alongside v1, both remain downloadable for the client.
  • Clicking Deliver on the revised version: item returns to "Delivered", order status recalculates (back to In Progress / Completed when no open revision requests remain), client receives in-app + email: "Your revised image is ready."
  • The existing Revision tab in Orders lists all orders with ≥1 open revision request.
Section 4 · Data & Validation
order_items.revisions_used → int, default 0
order_items.delivered_at → timestamp (drives the 7-day window)

revision_requests {
  id, order_item_id, note, reference_url,
  status: open | resolved,
  created_at, resolved_at
}

// Server-side validation (never trust the button state):
reject if revisions_used >= plan.max_revisions_per_image
reject if now() > delivered_at + 7 days
reject if order.status in (Approved, Cancelled)
reject if note.length < 20
