CTA flow · scroll first, signup at plan selection

Hero and section CTAs never fight scroll behavior with a modal. The flow is layered:

User clicks What happens
Hero CTA ("Get Your Free Image", "Get Your Free Strategy", "See Pricing") Smooth scroll to #pricing section. No modal. User lands on the pricing cards.
Plan CTA on a pricing card ("Claim Free Image", "Get Campaign 5", "Get Campaign 10") If signed in: go straight to New Order flow with plan preselected. If not signed in: open signup modal, then continue to New Order after successful signup.
Custom "Contact Us" Route to /contact?intent=custom. Signup optional (contact form can be filled by anyone).
Custom "Book a Call" / Deep Dive "Book a Call" Open Calendly popup (no signup gate). Calendly captures email itself.

Rationale: The hero CTA is an interest signal, not a purchase intent. Forcing signup there breaks trust and inflates bounce rate. Signup naturally belongs at the moment a plan is chosen, which is when the value exchange begins (create account = we can deliver your order).

// Hero CTA
<a href="#pricing" class="cta cta-primary">Get Your Free Image →</a>

// Plan CTA (with signup gate)
const handlePlanClick = (plan) => {
  if (!user) {
    openSignupModal({ onSuccess: () => startNewOrder(plan) });
  } else {
    startNewOrder(plan);
  }
};

<button onClick={() => handlePlanClick('campaign-5')}>Get Campaign 5 →</button>
6 · API Endpoints

Auth

POST /api/auth/signup // email, password, name → creates account
POST /api/auth/signin // email, password → JWT
POST /api/auth/social // provider, token → JWT
POST /api/auth/signout // revokes JWT
GET /api/auth/me // current user profile

Orders + Plans

GET /api/plans // public 5 tiers (Free · Brand Strategy · Campaign 5 · Campaign 10 · Custom)
GET /api/orders // user orders
POST /api/orders // create new order (plan, brief, strategy toggle)
GET /api/orders/:id // order detail
PATCH /api/orders/:id // update (status changes, cancel)
⚠ FREE IMAGE — 1 PER ACCOUNT, EVER
Enforce on POST /api/orders when plan === 'free_image'. Reject the order if the user (or their fingerprint) has ever created a completed Free Image order. Check across email address, billing name + address, phone number, and payment method fingerprint — any match blocks the second free order. Also enforce upstream at signup, so a duplicate account can't be created just to claim another Free Image.

Response on block: 409 Conflict · {"error": "free_image_already_claimed", "message": "Free Image already claimed on this account. Order a Campaign or Brand Strategy tier to continue."}

Log all blocked attempts to fraud_review table for admin review. Attempted fingerprints (email, phone, payment) get added to a shadow blocklist so the same actor can't retry with different combinations.

Brand Strategy

GET /api/brand-strategy/snapshots // user's delivered snapshots
POST /api/brand-strategy/request // standalone request (form data)
GET /api/brand-strategy/status // current in-progress state
POST /api/brand-strategy/deep-dive // inquiry submission

Admin

GET /api/admin/dashboard // 5 KPIs (Revenue · Orders · Clients · Images · Strategy Requests)
GET /api/admin/strategy-requests // list with status filter
GET /api/admin/strategy-requests/:id // detail
PATCH /api/admin/strategy-requests/:id // update status, notes (assignee is auto-set to Raluca on creation)
POST /api/admin/strategy-requests/:id/upload // upload PDF
POST /api/admin/strategy-requests/:id/send // send to client
POST /api/admin/strategy-requests/:id/flag-deep-dive // mark as "Converted to Deep Dive" + fire client nudge email with Book a Call CTA
GET /api/admin/analytics/strategy // strategy KPIs
// Buyer intros: no endpoints — handled off-platform by email after the Deep Dive kickoff call
GET /api/admin/plans // all 5 plans (admin view)
PATCH /api/admin/plans/:id // update plan fields + strategy toggles
